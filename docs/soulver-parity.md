# Soulver parity inventory

Tracking: [#33](https://git.oklabs.uk/BeFeast/figori/issues/33). Reviewed 2026-09-17 against the official [product](https://soulver.app/), [documentation index](https://documentation.soulver.app/llms.txt) and linked reference pages. Figori source baseline: desktop branch `ae098a4` plus concurrent fixes; this is an inventory, not a release acceptance report.

The requested scope is **all released Soulver feature families**, not merely arithmetic or a visual resemblance. Current targets are macOS and Linux; iPhone/iPad parity remains explicitly missing, not silently excluded. Windows/web are additional potential Figori targets, not advertised Soulver parity obligations. The live index also lists future “Soulver 5 (2027–2028)” and experimental X pages: those need separate release verification and are not counted as released requirements here. Marketing/documents can drift; refresh this inventory at each milestone.

Status: **current** means the stated narrow capability exists in inspected source; **partial** means only a subset exists; **missing** means no implementation found in the inspected packages. None means independently verified complete Soulver compatibility. Proposed acceptance examples below are synthetic specifications, not claims that current Figori passes them.

## Implementation sequence and closure

1. **P0 Reliability and executable inventory:** finish immediate PR32 acceptance; convert each matrix row into an owned child issue plus synthetic fixture manifest. Record parser vs document vs native UI vs provider evidence separately. Include reference revisions; no broad “all supported” claims from one worksheet.
2. **P1 Worksheet semantics:** prose/comments, multi-word variables, stable line references, totals/subtotals/tags, percent phrases, regional numbers, display formatting. Add graph/cycle/reorder tests before expanding grammar.
3. **P2 Offline calculator:** dimensional unit registry and custom units; function catalog; time/clock/workday/trip/video; finance formulas. Split domain registries from parser. Use exact decimal/rational representation and explicit date context.
4. **P3 Native documents and productivity:** library/search/windows, contextual menus/scrubbing, PDF/print/HTML/image export, automation Services/Shortcuts/deep links, accessible keyboard behavior. Verify AppKit/VoiceOver and Linux equivalents separately.
5. **P4 Data and resilience:** broaden FX/history; licensed market/crypto/weather/knowledge/CPI/tax sources; versioned caches, rate limits, credentials, attribution and explicit stale behavior. No paid subscriptions or server deployments merely to mark a checkbox complete.
6. **P5 Sync and Apple mobile:** conflict-safe storage/sync, backup restore UI, iPhone/iPad target and input modes. Apple entitlements/developer account and Linux interoperability are explicit dependencies, not assumed available.
7. **P6 Studio/distribution and final audit:** standalone-sheet packaging, platform-specific acceptance, migration/rollback, performance budgets and every documented feature/function/unit disposition. Experimental/future features remain a separately reviewed track.

Do not copy proprietary implementation, branding or assets. Functional parity is an independent implementation. Preserve Figori's accepted contextual calendar policy: the Soulver unit catalog lists average fixed month/year coefficients, but that must not silently replace anchor-based calendar calculations. Default today must remain visible and editable; monthly billing must retain its explicit include-partial choice. Data-dependent results disclose source/date/context. Unsupported syntax remains visible and source text stays intact.

This matrix is comprehensive at feature-family level. It is **not** a completed per-function/per-unit conformance suite or an estimate of delivery time; P0 expands catalogs into testable rows before any full-parity completion claim.
